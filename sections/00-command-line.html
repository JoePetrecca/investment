Section 00

Linux Basics

Everything in this guide happens in a terminal at some point. This section is your foundation: how to move around, manage files, chain commands together, and not be scared of the blinking cursor.

Start learning Back to sections
00

The terminal looks intimidating, but it runs on a tiny vocabulary. Maybe 15 commands cover 95% of what you will ever do. Learn these once and every other section of this guide gets easier: WSL, remote machines, tmux, environments, all of it is just these commands.

Tip You cannot really break anything by looking around. Navigating and listing files is completely safe. The only commands that need respect are the ones that delete things, and we will flag those clearly.

The mental model

Your computer's files are a tree. Folders (called directories in Linux-speak) contain files and other directories. At any moment, your terminal is "standing" in exactly one directory, called your working directory. Most commands act on whatever is around you, unless you point them somewhere else.

Three special names to know:

  • ~ is your home directory, your personal base camp
  • . is the directory you are standing in right now
  • .. is the directory one level up

Moving around

pwd: where am I?

Prints your current location as a full path. When in doubt, run this first.

Print working directory
pwd

ls: what is here?

Lists the files and directories around you.

List files
ls

The upgraded version you will use constantly: -l gives a detailed list (sizes, dates, permissions), -a also shows hidden files, whose names start with a dot, like .bashrc.

List everything, with details
ls -la

cd: go somewhere

Change directory. Give it a place to go:

Go into a folder
cd my_project
Go up one level
cd ..
Go home from anywhere
cd ~
Go back to where you just were
cd -
Tip The workflow loop is: pwd (where am I?), ls (what is here?), cd (go there), repeat. That loop is 80% of terminal life.

Making and managing files

mkdir: make a directory

Make a folder
mkdir analysis

Need nested folders in one shot? -p creates the whole chain, including any missing parents:

Make nested folders
mkdir -p project/data/raw

touch: make an empty file

Create an empty file
touch notes.txt

cp: copy

Pattern: cp source destination.

Copy a file
cp results.csv results_backup.csv

Copying a whole directory needs -r (recursive):

Copy a folder and its contents
cp -r project/ project_backup/

mv: move or rename

One command, two jobs. Move a file somewhere, or "move" it to a new name, which is how renaming works in Linux.

Move a file into a folder
mv results.csv data/
Rename a file
mv draft.txt final.txt

rm: delete

Delete a file
rm old_notes.txt
Delete a folder and everything in it
rm -r old_project/
Warning There is no trash can. rm is permanent and instant. Read the command twice before hitting enter, especially with -r. And never run rm -rf on a path you are not 100% sure about; it force-deletes without asking.

Looking inside files

cat: dump the whole file

Prints the entire file to your screen. Great for short files.

Show a file
cat notes.txt

less: scroll through a big file

Opens the file in a scrollable viewer. Arrow keys to move, /word to search, q to quit. This is what you use when cat would flood your screen.

Page through a file
less big_log.txt

head and tail: just the edges

First 10 lines, or last 10 lines. Perfect for peeking at a CSV.

First 10 lines
head data.csv
Last 20 lines
tail -n 20 data.csv

The killer feature: tail -f "follows" a file live, printing new lines as they appear. Perfect for watching a log while a long job runs.

Watch a log in real time
tail -f training.log

wc: count things

wc -l counts lines. How many rows in that CSV?

Count lines
wc -l data.csv

Finding things

grep: search inside files

Prints every line containing your search text. This one is worth its weight in gold.

Search one file
grep "error" training.log

Search every file in a whole project: -r searches recursively, -n shows line numbers, -i ignores case.

Search a whole folder
grep -rni "todo" .

That example finds every "TODO", "todo", or "ToDo" in the current directory (that is the .) and tells you the file and line number for each.

find: search for files by name

Find files by name pattern
find . -name "*.csv"

That lists every CSV file anywhere under your current directory, no matter how deeply nested.

Piping and redirecting: the superpower

Here is the big idea of Unix: every command reads a stream of text in and writes a stream of text out. You can plug them into each other like Lego bricks.

The pipe: |

The pipe takes the output of one command and feeds it into the next. Read it as "and then."

Count how many CSVs are here
ls | wc -l

"List the files, and then count the lines." Since ls outputs one name per line, that counts your files.

Find errors, keep only the recent ones
grep "error" training.log | tail -n 5

"Find every error line, and then show me just the last five." You can chain as many pipes as you want:

Triple chain
cat data.csv | grep "2026" | wc -l

"Show the file, keep only lines mentioning 2026, count them."

Redirecting: > and >>

Instead of printing to the screen, send output into a file. > creates or overwrites the file; >> appends to the end.

Save output to a file (overwrite)
grep "error" training.log > errors.txt
Add to the end of a file
echo "run finished at 3pm" >> lab_notebook.txt
Warning A single > silently wipes the target file before writing. If the file mattered, it is gone. When adding notes to an existing file, you almost always want >>.

sort and uniq: classic pipe partners

Unique values, counted, most common first
sort names.txt | uniq -c | sort -rn

This trio is a mini data analysis: sort the lines, collapse duplicates while counting them, then sort by the counts. It is a value-counts operation with zero Python.

Quality of life

These are not commands, they are habits. Learn them early.

Tab Autocomplete. Type the first few letters of a file or command and hit Tab. Never type a full filename again.
Up arrow Cycle back through your previous commands. Re-run without retyping.
Ctrl + C Kill whatever is currently running. Your escape hatch when something hangs.
Ctrl + R Search your command history. Start typing and it finds the matching past command. Magic.
Ctrl + L Clear the screen. Same as typing clear.
q Quits most viewers, like less, man, and top. If you feel stuck, try q.

Wildcards

* means "anything." It works with almost every command:

Move all CSVs into a folder
mv *.csv data/
List all Python files
ls *.py

history: what did I do?

Show past commands
history

Combine with grep to find that command from last week:

Search your history
history | grep "mamba create"

man and --help: the built-in docs

Every command documents itself. man ls opens the full manual (quit with q); ls --help prints a quick summary.

Read the manual
man grep

Checking on your machine

top: what is running?

A live view of every running process and how much CPU and memory each is using. Quit with q. On many systems, htop is a prettier version worth installing.

Live process viewer
top

df and du: disk space

How full are my drives?
df -h
What is taking up space here?
du -sh *

The -h means human-readable: sizes in MB and GB instead of raw bytes. du -sh * is the one to run when a cluster emails you about your storage quota.

which: where does a command live?

Shows the file path of the program a command actually runs. Extremely useful for debugging "which Python am I using?"

Which python is active?
which python3

Fun little commands

Not required. But the terminal should feel like home, and home has toys.

A calendar in your terminal
cal
Your folder structure as a tree
tree

(tree may need installing: sudo apt install tree. Genuinely useful for seeing project structure at a glance. ls -R works too)

The weather, in your terminal
curl wttr.in
A cow says whatever you want
cowsay "hello world"
A steam locomotive punishes your typos
sl

cowsay and sl also need installing (sudo apt install cowsay sl). sl exists purely to run a train across your screen when you typo ls. This is the culture you are joining.

The cheat sheet version

  • pwd / ls / cd — where am I, what is here, go there
  • mkdir / touch — make folders and files
  • cp / mv / rm — copy, move or rename, delete (carefully)
  • cat / less / head / tail — look inside files
  • grep / find — search inside files, search for files
  • | / > / >> — chain commands, save output, append output
  • Tab / Ctrl+R / man — autocomplete, search history, read docs
Tip Do not memorize this page. Bookmark it, then go use the terminal for real work. Within two weeks these commands will be in your fingers, not your notes.
