Section 02

Visual Studio Code

VS Code is the main editor for this workflow. The point is not just to write code. The point is to make programming, debugging, collaboration, and remote work feel smoother.

Read section Download VS Code
02

We use Visual Studio Code, usually called VS Code.

Reasons to use VS Code

  1. Everyone being on the same platform helps a lot. When you run into an issue, someone else has almost definitely seen it before. That makes debugging, helping each other, and sharing workflows way easier. You are not stuck figuring things out alone.
  2. VS Code also has a massive community. If something breaks or feels confusing, you can usually search it and find an answer immediately. That alone saves a huge amount of time.
  3. Another big reason we use it is extensions. There are extensions for pretty much everything, so you can customize VS Code into exactly what you need.
  4. It also has tools like Git integration built in, plus support for things like GitHub Copilot if you want AI-assisted coding.
Tip The goal is not just to write code. It is to remove friction so you can focus on the actual problem you are solving.

One of the biggest advantages for us is Remote SSH. This lets you connect directly to remote machines like ICER and Moria from inside VS Code. Once connected, it feels like you are working locally, even though everything is running on a supercomputer.

Warning If you are not using Remote SSH to access remote systems yet, you are probably making things harder than they need to be.
